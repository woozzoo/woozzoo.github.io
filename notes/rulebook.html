검수 통과와 완료는 다르다

"다 됐습니다"라는 보고를 믿을 수 있게, 완료·검수·상태의 기준을 규칙판으로 만들었습니다.

두 AI가 모두 "통과"라고 했는데 정작 요청한 개수가 모자란 일이 있었습니다. 검수는 산출물이 맞는지를 볼 뿐, 요청을 다 채웠는지는 보지 않았습니다.

규칙판의 핵심

  1. 검수 통과와 완료는 다르다. 끝났다고 하기 전에 원래 요청의 분량·개수·형식·위치를 실제로 세어 대조한다.
  2. 교차검수는 횟수와 멈출 조건을 정한다. 지적 → 수정 → 재확인이 한 회차, 기본 최대 3회차.
  3. 확인 수준을 밝힌다. 읽음 / 코드가 있음 / 빌드함 / 화면에서 봄 / 실제 결과를 받음.
  4. 같은 방법으로 3번 실패하면 방법을 바꾼다.
  5. 보냄 / 받음 / 실행함 / 검증함 / 완료를 나눠 쓴다.
  6. 새 세션은 인계서를 읽고, 승인된 범위만 이어 간다.
  7. 태산과 복길의 지침에 같은 규칙판 날짜를 둔다.

규칙에 날짜를 붙여 "판"으로 관리합니다. 한쪽 AI의 지침만 바뀌어 둘이 다른 기준으로 일하는 일을 막기 위해서입니다.
